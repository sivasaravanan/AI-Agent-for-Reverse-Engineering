# AI Software Engineering Agent (Phase 1)

Desktop tool that inspects a ZIP archive of a software project **statically** and produces an engineering
overview: languages, frameworks/runtimes, database clues, dependency manifests, syntax errors, TODO markers and
heuristic security warnings. Reports are written as HTML and JSON.

**No code from the archive is ever imported, executed or extracted to disk.**

## Requirements
- Python 3.11+ (tested on 3.12) with Tkinter (included in the python.org Windows installer)
- Runtime: standard library only. Tests: `pytest`

## Run (Windows)
```bat
cd ai_software_engineering_agent
python app.py                     :: GUI
python app.py --cli sample_project.zip --out reports   :: headless
scripts\run.bat                   :: same as python app.py
```
In the GUI: **Select ZIP / archive...** (zip, tar.gz) or **Select folder...** -> **Analyze** -> review the tabs (incl. **Code map**) -> **Open HTML report**. CLI: `--cli <zip|tar|folder> --docs`.
Reports are saved in `reports/` (override with `--out`).

## Test
```bat
scripts\test.bat
```
or `python -m pip install -r requirements.txt` then `python -m pytest -v`.
UI smoke tests need a display; they skip automatically without one (on Linux: `xvfb-run -a python -m pytest`).

## Sample project
`sample_project.zip` (multi-language fixture with a deliberate syntax error, fake secrets and mixed DB clues) is
generated by `python scripts/make_sample_project.py`.

## How to read the confidence labels
| Label | Meaning |
|---|---|
| strong | Declared in a manifest, or an explicit connection string/config targets it |
| moderate | Driver imported/used in code, or implied by a marker file/import |
| weak | Driver only declared in a manifest, or mentioned in a comment/doc |

Findings carry `confidence` and `verification`. Only parser results (Python syntax) are `confirmed`;
security-pattern results are `unverified-heuristic`.

## Layout
`core/` analysis logic (GUI-independent) | `security/` archive validation + redaction | `models/` data classes |
`services/` logging | `ui/` Tkinter | `tests/` unit, integration, security, fixtures. See `DEVELOPMENT_STATUS.md`.

## Phase 2 - structure and dependencies (added in 0.2.0)
The analysis now also reports: a capped directory tree, entry points, configuration-file inventory, imports and
module relationships (Python, JS/TS, C#/VB.NET, Java, Go, PHP), circular imports, external packages vs declared
dependencies, environment-variable references (names only), database connection configuration (secrets redacted),
a per-language/framework/database evidence class (**confirmed / strong / weak / unknown**) and configuration warnings.
They appear in new GUI tabs, in the HTML report, and under the `structure` key of the JSON report.

| Evidence class | Meaning |
|---|---|
| confirmed | two independent evidence types agree (e.g. declared in a manifest AND imported in code; connection config AND driver used in code) |
| strong | one solid evidence type (declared only, or configured only) |
| weak | driver/mention only - not proof a database is configured or used |
| unknown | not determinable from the archive |

## Phase 8 - human-approved code correction (added in 0.3.0)
Fixes are proposed, reviewed and applied only with your explicit approval, and only to an editable **workspace copy**
(the original ZIP is never modified).

GUI: analyze a ZIP, select a finding, click **Propose fix...**, choose an empty folder, read the colored diff, tick the
approval box, then **Apply and verify**. **Revert** restores the backup.
CLI: `python scripts/fix_cli.py project.zip --workspace C:\work\fixes --list`, then `--finding F-0003`
(asks `y/N` after showing the diff); undo with `--revert <workspace>\.ase_backups\<stamp>_<id>\manifest.json`.

Safeguards: approval + shown-diff + unchanged-file checks; backup and hash manifest before writing; atomic writes;
automatic rollback when the patch adds a high/critical finding or (with an isolated runner) breaks a passing test.
Verification is reported honestly: without an isolated test runner (Phase 4) the result is **NOT VERIFIED** - only a
static before/after comparison is made and no project code is run.
Automatic proposals exist for: TLS verify off, DEBUG on, yaml.load, hardcoded secrets (Python), eval (Python).
Syntax errors and other rules need manual edits (AI-assisted patches arrive with Phase 7 and will be marked unverified).


## Phases 3-8 (merged)
Run `python app.py` (GUI) or `python app.py --cli project.zip`. Tabs: Overview, Findings, Structure..., Static tools, Databases,

AI: enable in the AI tab; keys come from an environment variable named in settings or are typed per session (never saved).
